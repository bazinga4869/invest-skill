# 报告准出规则

仅在生成草稿、裁判、自评审或排查发布失败时读取。

## 自评审（总分 90）

- 数据可追溯性 25：数字无 JSON 路径每个 -8；单位错误每个 -10；无来源行业/历史断言每个 -10。
- 方法论忠实度 25：结论违背 wiki 每个 -15；漏必检项每个 -8；触发 VETO 未标注每个 -20。
- 裁判诚实性与一致性 25：忽略关键否定意见每个 -15；专家矛盾未处理每对 -10；前后数据不一致每处 -10。
- 逻辑与表述 15：循环论证/因果倒置每处 -5；专家核心发现遗漏每位 -10；知识日志少于 3 条每位 -5。

草稿末尾必须包含 `## 结构化自评审`、得分表、扣分明细、独立行 `**总分：XX / 90**` 和独立行 `**判定：PASS**`。分数只允许 72-90；`BYPASS` 等包含 PASS 的字符串不能通过。只有 ≥72 且机器门禁 PASS 才准出；其余必须修正后重跑。

## 机器门禁

1. `collect_results.py --check`：七份结果均满足 frontmatter、`data_date`、`batch_id`、章节、精确引用和必检项；VETO 的 `veto_triggers` 必须是非空字符串列表。
2. `checklist_audit.py --code`：每位专家结构化必检项覆盖率至少 80%。项目名须原样保留，状态为 DONE，证据须同时通过该项语义规则和真实路径/文档定位验证；MISSING 不计覆盖。
3. `collect_challenges.py`：7 份二级质询必须绑定原专家报告 SHA-256，逐字保留 3 个问题，且回应为 150-300 个中文字。
4. `verify_report.py --strict`：每个事实数字以紧邻其后的 `[source: JSON.path]` 溯源；同一行的来源不能互换。推导值使用可执行的 `[calc: (current/previous-1)*100; inputs: JSON.path,JSON.path]`，验证器必须重算到报告显示精度且结果单位匹配。数组下标路径完整解析；无来源历史/行业断言为失败。
5. `assemble_report.py --finalize`：重复上述检查，验证综合裁决 YAML、七份专家原文和七份质询回应均唯一嵌入、三级触发判定与机器重算一致；如触发，3 份交叉盲审必须绑定输入/prompt 哈希并逐字聚合。通过后才原子发布并归档 manifest。不存在 `--allow-missing` 绕过路径。
6. `verify_manifest.py <正式报告>`：验证报告引用的 manifest 存在、路径未越界，数据/年报/7 专家 prompts/results/7 质询 prompts/results/三级判定/draft/final 证据齐全；第三级触发时还必须包含 3 份交叉盲审 prompts/results 和聚合原文。每个文件大小/哈希必须正确，正式报告与归档副本必须一致。
